 Sankalan(collection/compilation) Deep Learning-Based Synthetic Data Generation &amp; Analytics Platform Domain: Data Augmentation | Project Type: Generative AI + Deep Learning + Data Analytics 1. Project Overview Sankalan is an interactive platform that generates realistic synthetic tabular data using Deep Learning and evaluates the generated data against the original dataset. The platform combines data cleaning, exploratory data analysis, a Variational Autoencoder (VAE), statistical comparison, and an interactive analytics dashboard. Primary goal: Generate additional synthetic records that preserve important statistical patterns and relationships in the original data, then quantitatively evaluate whether the synthetic dataset is useful for analytics and downstream data-science tasks. 2. One-Line Project Definition Sankalan generates realistic synthetic tabular data using Deep Learning and evaluates its statistical similarity, data quality, and analytical usefulness against the original dataset through an interactive dashboard. 3. Problem Statement Real-world datasets may be small, incomplete, imbalanced, difficult to share, or sensitive. Simply creating random records does not preserve the relationships present in real data. Sankalan learns patterns from an original dataset and generates new records intended to retain useful statistical characteristics without simply duplicating existing rows. 4. Proposed Solution Upload a CSV or Excel dataset. Profile and clean the dataset. Perform automated exploratory and statistical analysis. Preprocess numerical and categorical variables. Train a Variational Autoencoder (VAE) using Deep Learning. Generate a configurable number of synthetic records. Compare original and synthetic datasets. Calculate statistical, distributional, and correlation-based similarity measures. Provide interactive visualizations and a synthetic-data quality report. Allow users to download the generated synthetic dataset and evaluation results. 5. Module 4 â€” Deep Learning Synthetic Data Generation The primary generative model should be a Variational Autoencoder (VAE). A VAE is selected because it is a Deep Learning generative model, is easier to train and explain than a GAN for a time-limited college project, and provides a clear latent-space generation workflow. Concept: Input data â†“ Encoder â†“ Latent representation (Î¼, Ïƒ) â†“ Sampling â†“ Decoder â†“ Reconstructed / generated data High-level VAE architecture: Input layer = number of processed features Encoder dense layers Latent mean (mu) Latent log-variance (log_var) Reparameterization trick Decoder dense layers Output layer matching the processed feature representation 11. VAE Training The VAE objective contains two main components: Reconstruction loss: measures how well the decoder reconstructs the input. KL-divergence loss: regularizes the latent distribution toward a standard normal distribution. The combined loss is minimized during training. Training history should be stored and displayed so the team can demonstrate model convergence. 12. Synthetic Data Generation After training, sample points from the latent distribution and pass them through the decoder. Convert the generated values back to the original feature representation and data types. Example: Original records: 10,000 Requested synthetic records: 20,000 Model: VAE Output: synthetic CSV/XLSX 13. Limitations to State in the PPT Synthetic data quality depends strongly on the original dataset and preprocessing. A VAE may not perfectly reproduce complex distributions. Synthetic data is not automatically equivalent to real data. Statistical similarity does not guarantee business usefulness. Generated data should be evaluated before being used for real-world decisions. The project is a prototype and not a replacement for production-grade synthetic-data validation. 36.
